# Progress

## Phase 1: Foundation (in progress, nearly done)

### Done
- Scaffold: two Vite entries (`index.html` public, `app.html` staff/HQ), strict TS (app / server / node projects), oxlint, Vitest projects (unit, integration, rules).
- API: one Vercel function `api/index.ts` lazy-loading one-file-per-route handlers in `api/_routes/` (table generated by `npm run routes`); `lib/http/route.ts` does auth, branch scoping, `can()`, strict zod bodies, idempotency keys, demo locks. Vite plugin runs the same API and `middleware.ts` locally.
- `shared/`: money, FX, currencies, locales, country profiles (with `lastReviewed`), settings merge, `calculateBill` / `priceBill` + cash rounding + splits (34 worked examples), time zones / business day / opening hours, phone (4 countries + E.164), TW e-invoice validators, numbering, permission matrix, menu rules, daily summary.
- Auth: PBKDF2 passwords and PINs, signed session and device cookies, PIN switch bound to a device, manager approvals, Firebase custom tokens, demo one-tap login.
- Firestore rules (+ 11 emulator tests: a Jakarta cashier can't read Singapore), indexes with TTL, storage rules.
- i18n: 7 guest + 5 staff files, type-checked shape; Latin fonts self-hosted, CJK via Google Fonts per locale.
- Front end: public placeholder in 7 languages with demo ribbon and STOEDIO credit; staff app with login + demo grid, device registration, PIN lock screen, branch shell (role and permission tiles), HQ shell, dark/light themes.
- Seed: `npm run seed` writes ~76k documents in ~2 min (5 branches, 46 master items × 7 languages, branch menus + 15 specials, 39 ingredients, stock, suppliers, 63 staff, 600 guests, FX, 60 days raw history, a year of summaries/expenses, today so far, a week of bookings).
- Demo: `cron/nightly` rolling reset (visitor docs deleted, yesterday completed, oldest day dropped, baseline restored, deploy-hook check); throttled catch-up keeps "today" filled. Estimated ~3.1k writes/night (unit-tested under 5k).

### Assumptions and changes from the plan
- CJK fonts load from Google Fonts per locale (self-hosting them would add tens of MB per build); Latin fonts are self-hosted.
- No `reservationCodes` collection: uniqueness is checked with a query in the booking transaction.
- Seeded bill numbers for today reserve the whole day's planned range; live bills continue after it.
- Labour cost uses fully loaded hourly rates; employer contributions are a monthly "statutory" expense.
- Holiday dates (2026–27) are seeded with `verify: true`.

### Known issues
- Device revocation takes up to 30 s (instance cache), by design.
- The dispatcher's Vercel deployment (rewrite to `/api?__path=`, `_routes` not deployed as functions) is untested until the first deploy.
- The shared JS chunk is ~85 KB gzip; the public homepage budget is checked in Phase 2.

### How to test by hand
1. `cp .env.example .env.local` and set `SESSION_SECRET` (32+ chars) and `CRON_SECRET`.
2. Terminal 1: `npm run emulators` (needs Java 21; the script finds Homebrew's `openjdk@21`).
3. Terminal 2: `npm run seed`, then `npm run dev`.
4. Open `/login` and tap any role. Passwords are `bara-demo-2026`; PINs: manager 2468, cashier 1357, waiter 1470, kitchen 2580, host 3690.
5. Nightly job: `curl -H "Authorization: Bearer $CRON_SECRET" localhost:5173/api/cron/nightly`.
